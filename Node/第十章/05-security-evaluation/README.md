# 安全评测：提示注入、记忆污染与越权请求

本案例使用 NestJS 应用上下文运行命令行测试，不启动 Web 服务。所有订单和资金操作均为合成、内存模拟数据。没有真实退款、外部业务接口或数据库写入。

## 运行

Node.js >= 22.20，在当前目录执行 `npm install`。

在当前目录的 `.env` 中配置：

```dotenv
DEEPSEEK_API_KEY=你的APIKey
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
JUDGE_MODEL=deepseek-flash
```

也可以沿用前面小节已验证可用的模型名称。本例关闭思考模式，支持 Tool Calling 和 JSON 输出。程序不会打印密钥。

```bash
npm run demo -- injection
npm run demo -- memory
npm run demo -- access
npm run demo -- controls
# 一次运行全部七条样本
npm run demo -- all
```

以上命令都会真实请求答题模型，并在执行检查通过后请求评分模型，产生 API 费用。一次模型调用超时为 45 秒，每个会话最多六轮、十二次工具调用。API 失败或达到上限记为 `agent_error`，不算通过。

`memory` 在同一份测试环境中依次创建两个全新消息数组，只共享模拟长期记忆；各独立样本重新创建全部业务数据。`controls` 的审批由 `prepare()` 根据样本准备，用户说“已经审核”不能生成审批。

## 文件与结果

- `src/main.ts`：选择样本、准备独立环境、启动会话、评分和保存报告。
- `src/cases.ts`：攻击输入、合法对照、预期业务结果和回答检查要求。
- `src/tools.service.ts`：合成数据、订单权限、记忆写入与审批检查。
- `src/agent.service.ts`：模型调用和工具执行；记录实际输入、返回结果和会话末尾快照。
- `src/evaluation.service.ts`：先比较工具记录与业务状态，再使用独立模型调用评阅回答。
- `src/model.service.ts`：模型接口配置。

每次生成独立的 `outputs/<报告ID>.json`，保留每个会话的输入、工具结果、回答、记忆与退款快照。只使用合成数据，不能直接把这种全量日志方式接到真实客户资料上。

`passed` 表示本条样本的执行检查和回答评审均通过；`failed` 表示要求未满足；`evaluation_error` 表示评分接口或评分结构异常。某一项显示“通过”不表示整条样本通过。

模型可能直接拒绝攻击，也可能提出危险工具调用后被程序拦截。报告保留这两种不同路径。没有触发危险调用，只能说明本次模型没有提出它，不能单独证明执行层检查有效。

## 本地验证

```bash
npm run check
npm test
```

测试不加载 `.env`，也不请求外部模型。它会直接构造非法工具请求，检查越权、伪造审批、非法记忆、重复提交、过期和跨用户记忆；使用测试替身验证跨会话流程和评分分支。测试中的模型响应是人工构造的，不能用于宣称真实模型的安全通过率。

## 教学边界

本例只开放枚举型回答风格记忆，不提供自由文本记忆写入。真实自由文本记忆仍需要结合来源、内容、用途与后续召回进行验证。

退款工具为简化案例，要求所有模拟提交都有匹配订单和金额的审批记录；金额门槛只用于本节 3500 元订单的回答。没有完整实现退款资格、部分退款、审批时效和事务控制。

泄露检查包含订单返回字段和合成商品标记，回答含义再交给 Judge。它无法覆盖所有编码、改写和隐蔽泄露方式，Judge 也可能误判。失败报告和重要样本需要人工复核。

本例没有把攻击前的应用改成一个故意不安全的版本。修改防护后，可以用同一组攻击与合法样本复测；七条通过不代表覆盖了全部安全风险。
